# Development Leads — private research import, v1

One local UTF-8 JSON file. This is a screen, not zoning approval, title, availability, vacancy, or tenant delivery. Never put a real file in this repository, assets, a preview or a build. The importer normalizes the reviewed fields below and ignores additional source-only metadata. Maximum 150 ranked **sites** and 1.8 MB uncompressed file; ranks positive and unique. No upper unit threshold. Use `null` for an unknown scalar/range, not zero. An SF range is `{ "min": number, "max": number }`; estimates are not zoning determinations.

- Envelope: `schema_version: 1`, `generated_at` ISO date or timestamp, optional `label`, `methodology`, `leads` array. `id` must stay constant across updates for the same site/scenario, independent of rank, wording, or date (e.g. stable hash or BBL scenario key). Do **not** reuse an ID for another assemblage or a different retained donor set. Retain rank/identity if merely correcting source facts. IDs use lowercase letters, digits, hyphen, dot, underscore or colon; max 96 characters.
- Each lead: `id`, `rank`, `type` (`standalone`, `sandwich`, `air_rights`, `fallback`), `anchor: { address, bbl }` (BBL ten-digit string), `borough` (official name), `existing_units` (redevelopment parcels only), `frontage_ft` and `depth_ft` (anchor), `lot_area_sf` (anchor), optional `combined_area_sf`, `combined_frontage_ft` (redevelopment acquisition parcels only), `neighborhood`, `zoning`, optional `standalone_buildable_sf` (anchor-alone baseline for an assembly), `buildable_sf` range (new build zoning SF in this scenario, not existing/retained area), `target_units` (`{min,max,certainty}` with certainty `screened`, `concept` or `unconfirmed`), `why_call` (required), `fit`, `risks`/`assumptions` (string arrays), `sources` (at least one `{label,url}` HTTPS evidence link).
- `parcels` array: `{address,bbl,role,existing_units,area_sf,frontage_ft,ownership,geometry,sources}`. Exactly one `anchor` matching the anchor BBL. Other roles: `left`, `right`, `acquisition`, `donor`. Fill out both actual assembly neighbors where present; indicate common lot line or transfer uncertainty in `geometry`. Retained donors are not acquisition/demolition parcels. `ownership` is evidence text if documented, not a guess. Do not supply private contact information in source. If all acquisition lot counts are known, `existing_units` must equal their sum; no sites with more than ten. A fallback requires verified 50+ ft anchor frontage, with `target_units: null` or `unconfirmed`. Other types require a credible scenario reaching 30 units; the importer imposes no ceiling.
- `listing`: `{status,ask_usd,checked_at,source,note}`. Only `verified_listed` accepts a documented ask (or null) and requires a dated evidence link `{label,url}`. `not_found` requires date and **does not mean off market**. `unknown` is appropriate for unverified/blocker; no inferred ask. Dates ISO. Add precise evidence/caveats to note.
- `air_rights` for air rights only: `{transfer_verified:false, receiver_standalone_sf, donor_unused_sf, receiver_increment_sf, new_build_sf, confidence, title_risk, zoning_risk, envelope_risk}`. SF fields are ranges or null; confidence uses the unit-certainty terms. Donor unused ≠ transferable: plausible receiver increment is separate. `new_build_sf` excludes retained donor area and units. For UI 680 zoning SF/unit sensitivity, use the `new_build_sf` range; the app divides by 680 and rounds down, separately from a documented achievable planning range. Shared boundary, same zoning lot, third-party consent, prior transfers, zoning limits and receiving envelope must be checked, not inferred.
